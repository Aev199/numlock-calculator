# NumLock Calc

Компактный keyboard-first калькулятор для Windows. NumLock показывает окно, возвращает ему фокус или скрывает его. Выражение вычисляется во время ввода, а Enter превращает результат в новое рабочее значение и сохраняет исходное вычисление в историю.

Оболочка — **Python + pywebview/WebView2**. Node.js и Electron не нужны ни для запуска, ни для сборки EXE.

## Возможности

- безопасный AST-движок без `eval`;
- арифметика, функции, скобки, степени, факториал и проценты;
- `DEG / RAD / GRAD` и `DEC / HEX / OCT / BIN`;
- переменные, `ans` и 10 ячеек памяти;
- live-preview и оптимистический Enter;
- история с поиском, копированием, удалением и повторным редактированием;
- локальная командная палитра `Ctrl+K` и автодополнение;
- отдельный режим **«Единицы»**;
- компактное безрамочное окно, системный трей и режим поверх остальных окон;
- подавление физического NumLock с управляемым циклом LED OFF → ON и восстановлением цифрового режима.

## Режимы

### Калькулятор

Основной режим предназначен для обычных вычислений, функций, памяти, переменных и истории. Единицы измерения не выводятся в палитре, чтобы список команд оставался математическим и компактным.

```text
2 + 3 * 4
sin(30)
9!
200 + 10%
span := 6
span / 2
```

### Единицы

Вкладка **«Единицы»** использует то же поле ввода и результата, а вместо истории показывает категорию и исходную/целевую единицы.

Поддерживаются длина, площадь, объём, масса, время, температура, сила и давление.

Поле принимает только простую арифметику: числа, скобки, `+`, `−`, `×`, `÷`, степень и десятичную запятую. Функции, переменные и единицы внутри выражения не принимаются.

Последний подтверждённый числовой результат калькулятора переносится в режим «Единицы» один раз на новую ревизию. Ручное состояние конвертера не затирается при обычном переключении и сохраняется между запусками.

## Интерфейс и анимации

Renderer построен как одна постоянная сцена:

- поле ввода и результат не пересоздаются при смене режима;
- история и панель единиц постоянно находятся в DOM и переключаются через прозрачность;
- активный режим показывает единая перемещающаяся капсула;
- `textarea` не масштабируется и не перемещается;
- Enter анимирует только изолированную визуальную копию результата поверх неподвижного поля;
- новая строка истории создаётся один раз и затем превращается из локальной в сохранённую без полной пересборки списка;
- ввод даёт короткий отклик фона поля, не затрагивая растеризацию текста;
- `prefers-reduced-motion` отключает декоративное движение.

Все визуальные переходы запускаются после локального изменения состояния и не ждут записи JSON или ответа Python. Поздние ответы backend проверяются по ревизии, выражению и контексту единиц, поэтому не должны перезаписывать уже введённое новое значение.

## Управление

- **NumLock** — показать скрытое окно, вернуть фокус видимому окну или скрыть активное; после LED OFF → ON цифровой блок остаётся включённым.
- **Enter** — вычислить, подставить результат и сохранить исходное выражение в историю.
- **Ctrl+K** — открыть палитру команд при любой раскладке.
- **← / →** — переключать группы палитры.
- **↑ / ↓** — выбирать команду или перемещаться по истории.
- **Ctrl+Space** — показать автодополнение.
- **Escape** — закрыть подсказку, очистить поле или скрыть пустое окно.
- **Ctrl+Shift+Q** — аварийный полный выход.

В истории стандартные `DEG` и `DEC` не подписываются. Метка появляется только для `RAD`, `GRAD`, `HEX`, `OCT` или `BIN`.

## Архитектура

### Python

- `calc_engine.py` — безопасный парсер и вычислительное ядро;
- `calc_engine_runtime.py` — side-effect-free preview и каталог команд;
- `app.py` — базовый API и JSON-хранилище;
- `app_window.py` — фокус, видимость и активация окна без доступа к HTML;
- `app_numlock_compat.py` — низкоуровневый NumLock-hook и LED-цикл;
- `app_tray.py` — frameless-параметры и системный трей без модификации renderer;
- `unit_conversion.py` — каталог единиц и безопасная простая арифметика;
- `app_units_backend.py` — backend-only API конвертера и передача результата;
- `app_renderer.py` — единственный сборщик финального HTML;
- `app_keyboard.py` — точка входа и порядок установки независимых слоёв.

### Frontend

- `renderer/app-shell.html` — окончательная постоянная разметка;
- `renderer/app-shell.css` — единая система оформления и движения;
- `renderer/app-shell-v2.part00.js … part08.js` — упорядоченные исходные части одного IIFE-контроллера, которые `app_renderer.py` объединяет в один inline-скрипт.

Рабочая точка входа не импортирует старые `app_polish`, `app_compact`, `app_stability` или renderer-патчи. Python не модифицирует готовый HTML строковыми заменами, кроме детерминированной подстановки CSS и единственного собранного JavaScript-контроллера в заранее заданные placeholders.

## Запуск

Требуется Windows и Python 3.11–3.13.

```bat
py -3 -m venv
.venv\Scripts\python -m pip install -r requirements-build.txt
.venv\Scripts\python app_keyboard.py
```

## Сборка

Один EXE:

```bat
build.bat
```

```text
dist\NumLockCalc.exe
```

One-dir сборка:

```bat
build_onedir.bat
```

Полностью офлайн:

```bat
prepare_offline_wheels.bat
build_offline.bat
```

Данные сохраняются в `numlock-calc-data.json` рядом с EXE.

## Проверка

GitHub Actions проверяет компиляцию Python, вычислительный движок, API, NumLock/focus, renderer, tray, режим единиц, полный `unittest discover` и синтаксис собранного JavaScript-контроллера.

CI выполняется на Linux. Поведение WebView2, NumLock-hook, tray и субъективную плавность анимаций необходимо подтвердить собранным EXE на Windows.
