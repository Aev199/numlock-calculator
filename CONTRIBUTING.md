# Участие в разработке NumCalc

Спасибо за интерес к проекту.

## Перед началом

1. Проверьте существующие issues и pull requests.
2. Для заметного изменения сначала создайте issue с описанием сценария пользователя.
3. Не включайте в коммиты пользовательские данные, логи, EXE, архивы, виртуальные окружения и локальные настройки.
4. Для уязвимостей используйте порядок из [SECURITY.md](SECURITY.md), а не публичный issue.

## Среда разработки

NumCalc ориентирован на Windows 10/11 и Python 3.11–3.13.

```bat
py -3 -m venv .venv
.venv\Scripts\python -m pip install -r requirements-build.txt
```

Запуск:

```bat
.venv\Scripts\python app_keyboard.py
```

## Проверки перед pull request

```bat
.venv\Scripts\python -m unittest discover -s tests -v
.venv\Scripts\python generate_version_info.py
git diff --exit-code -- version_info.txt
```

Для изменений frontend дополнительно соберите объединённый JavaScript либо дождитесь соответствующей проверки GitHub Actions.

Изменения низкоуровневого NumLock-hook, окна, трея, автозагрузки или DPI должны сопровождаться ручной проверкой затронутых пунктов [docs/WINDOWS_ACCEPTANCE.md](docs/WINDOWS_ACCEPTANCE.md).

## Принципы проекта

- нативный и предсказуемый ввод важнее декоративных эффектов;
- универсальная логика предпочтительнее исправлений под один пример;
- вычислительное ядро не использует `eval`;
- пользовательские данные остаются локальными;
- новые сетевые функции не добавляются без явной необходимости и прозрачного описания;
- интерфейс должен оставаться пригодным для компактного окна;
- поведение клавиатуры не должно ломать стандартное редактирование, выделение, вставку, IME и accessibility.

## Стиль изменений

- Делайте один логически цельный pull request.
- Добавляйте тест на исправляемую регрессию.
- Обновляйте README, встроенную справку и CHANGELOG, когда меняется пользовательское поведение.
- Не изменяйте версию приложения в обычном feature/fix pull request.
- Не добавляйте сторонний код без проверки его лицензии и обновления `THIRD_PARTY_NOTICES.md`.
